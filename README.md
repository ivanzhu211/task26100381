# pixelforge

PixelForge 感知指纹近重检索库：对可信的 64 位感知指纹做**精确**的
汉明距离 ≤ 8 近邻检索。纯内存、单工作区、串行调用，不做持久化。

## 接口

```go
ix := pixelforge.New()
ix.Upsert(versionID, fingerprint) // 登记；versionID 已存在则替换指纹
ix.Remove(versionID)              // 移除
hits, evals := ix.Query(fp)       // 返回距离 ≤ 8 的全部版本、精确距离、本次完整求值次数
```

## 运行

```sh
go test ./...                    # 全部测试（含规模测试，约几秒）
go test -short ./...             # 跳过规模测试
go test -run TestScale -v .      # 只跑规模测试并打印计数/内存/耗时
```

## 索引结构：多索引哈希（MIH）

- 64 位指纹切成 4 个 16 位分带，每个分带一张 `map[uint16][]uint64`
  （分带键 → 该键下的版本列表），外加 `versionID → 指纹` 主表。
- **Upsert**：若版本已存在，先按旧指纹从 4 个分带桶中摘除（桶空即删键），
  再按新指纹插入 4 个桶。单条更新只动 4 个桶，不重建索引，立即生效。
- **Remove**：按当前指纹摘除 4 个桶并删主表项。
- **Query**：对每个查询分带键枚举汉明距离 ≤ 2 的全部
  1 + 16 + 120 = 137 个键（共 4 × 137 = 548 次桶查找），
  对命中的候选版本去重后逐一计算完整 64 位距离（每次求值计数，
  含重复计算——候选已去重，故每版本每次查询至多计一次），
  距离 ≤ 8 者入结果。

## 为什么不会漏检

若两指纹汉明距离 ≤ 8，把 8 个差异位分配到 4 个分带，由鸽巢原理
至少一个分带的差异 ≤ ⌊8/4⌋ = 2。查询枚举了每个分带距离 ≤ 2 的
**全部**键，因此任何真实命中必然落入某个被探查的桶，进入候选并被
完整求值。候选筛选只按分带键精确匹配，无近似、无抽样、无截断；
去重只用于避免重复求值，不丢弃任何版本。因此结果与逐个检查当前
所有版本完全一致。替换/删除同步维护分带桶，旧指纹立即失效，
不会残留旧索引项；空间为 O(当前版本数)，反复替换同一版本不增长。

## 性能与退化

规模测试（固定种子，100 万互异均匀指纹，1000 次查询各翻转 8 位）
实测：平均每次查询约 **8.3k** 次完整求值（预算 1 万），峰值内存约
**212 MiB**（预算 768 MiB），构建约 0.6 s，查询平均约 1.6 ms。
均匀分布下每桶期望 n / 65536 个版本，候选数 ≈ 548 × n / 65536。

最坏情况（指纹高度聚集，如大量版本共享少数分带键）候选集会退化
到接近全量，查询趋近 O(n) 暴力扫描——但结果仍然精确，只是变慢，
不会漏报或误报。这是精确检索在对抗性分布下的固有下界。
